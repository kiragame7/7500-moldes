Preciso que você corrija um bug de tracking no projeto (React + TanStack Start).

CONTEXTO DO BUG:
No arquivo `src/components/HomeContent.tsx`, os botões de checkout (que levam para
o Hotmart) são links <a target="_blank"> cujo onClick dispara `trackEvent(...)`
de forma "fire-and-forget" (com `void`, sem `await` e sem `event.preventDefault()`).
Isso faz o navegador começar a navegar para o href do Hotmart no mesmo instante do
clique, enquanto o `trackEvent` ainda está processando de forma assíncrona.

O `trackEvent` (definido em `src/lib/facebook.hooks.ts`) dispara duas coisas:
1. `window.fbq('track', ...)` — síncrono, sempre funciona.
2. `sendFacebookConversionEvent(...)` — uma Server Function (TanStack) que faz um
   `fetch` assíncrono para o backend, que por sua vez envia o evento para a Meta
   Conversions API (CAPI).

No desktop, a aba original costuma continuar viva tempo suficiente para esse
fetch terminar. No celular (principalmente dentro do navegador in-app do
Instagram/Facebook), o sistema operacional suspende ou mata o contexto JS da aba
de origem quase imediatamente ao navegar, cancelando o fetch antes dele
completar. Resultado: o Pixel do navegador ainda dispara, mas o evento nunca
chega via CAPI no celular.

O QUE FAZER:
Encontre TODOS os links de checkout em `src/components/HomeContent.tsx` que
seguem este padrão (são pelo menos 3: planos "Premium", "Premium_Upgrade" e
"Basic", cada um indo para uma URL diferente do Hotmart):

  
    href={withHotmartAttribution("https://pay.hotmart.com/...")}
    onClick={(event) => {
      const xcod = new URL(event.currentTarget.href).searchParams.get('xcod');
      void trackEvent('InitiateCheckout', { ...customData... }, getCheckoutEventId('...'));
    }}
    target="_blank"
    rel="noopener"
    ...
  >
    ...
  </a>

Para CADA um desses links, altere o onClick para:
1. Chamar `event.preventDefault()` no início.
2. Guardar `href` e `xcod` ANTES de disparar o tracking.
3. Fazer `await` no `trackEvent(...)`, mas com um timeout de segurança de 300ms
   usando `Promise.race`, para não travar o usuário se a rede estiver lenta.
4. Só depois disso, navegar manualmente com `window.open(href, '_blank', 'noopener')`.

Exemplo de como deve ficar (ajuste os dados de customData/getCheckoutEventId
para cada plano, mantendo os valores que já existem em cada botão):

  
    href={withHotmartAttribution("https://pay.hotmart.com/...")}
    onClick={async (event) => {
      event.preventDefault();
      const href = event.currentTarget.href;
      const xcod = new URL(href).searchParams.get('xcod');

      await Promise.race([
        trackEvent('InitiateCheckout', { plan: 'Premium', value: 9.99, currency: 'USD',
          content_ids: ['premium'], content_type: 'product', hotmart_xcod: xcod },
          getCheckoutEventId('Premium')),
        new Promise((resolve) => setTimeout(resolve, 300)),
      ]);

      window.open(href, '_blank', 'noopener');
    }}
    target="_blank"
    rel="noopener"
    ...
  >
    ...
  </a>

IMPORTANTE:
- Não mude os valores de customData (plan, value, currency, content_ids,
  content_type, hotmart_xcod) nem o argumento passado para `getCheckoutEventId`
  em cada botão — são diferentes para Premium, Premium_Upgrade e Basic. Só
  altere a lógica do onClick em volta.
- Não mexa nos botões de "ViewContent" (Hero, Footer, Básico), que já usam
  `event.preventDefault()` corretamente e não navegam para fora da página —
  o bug é específico dos links que saem para o Hotmart.
- Não altere `src/lib/facebook.hooks.ts` nem `src/lib/facebook.functions.ts`.
- Rode os testes existentes (se houver) depois da mudança para garantir que
  nada quebrou.
